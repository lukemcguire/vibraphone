# Requirements: Vibraphone

**Defined:** 2026-02-16
**Core Value:** Every code change goes through the quality gate (tests, lint, review) before it can be committed — enforced by tooling, not by prompting.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Package Foundation

- [ ] **PKG-01**: Package installable via `uv tool install vibraphone` from local path or git
- [ ] **PKG-02**: Package installable via `pip install -e .` for development
- [ ] **PKG-03**: `vibraphone` command starts FastMCP server on stdio transport
- [ ] **PKG-04**: Server starts without vibraphone.yaml present (zero-config, stays quiet)
- [ ] **PKG-05**: Source code organized in src/vibraphone/ layout
- [ ] **PKG-06**: All Python dependencies declared in pyproject.toml

### Configuration

- [ ] **CFG-01**: Server discovers vibraphone.yaml by walking up from CWD
- [ ] **CFG-02**: Config validates on load with clear error messages for invalid fields
- [ ] **CFG-03**: All config fields have sensible defaults
- [ ] **CFG-04**: Worktree base path configurable via vibraphone.yaml (default: ~/.vibraphone/worktrees/)
- [ ] **CFG-05**: Existing vibraphone.yaml format from template projects is compatible

### Task Management Tools

- [ ] **TASK-01**: Agent can list tasks with optional status filter (list_tasks)
- [ ] **TASK-02**: Agent can get next unblocked task (next_ready)
- [ ] **TASK-03**: Agent can mark task complete and see unblocked tasks (complete_task)
- [ ] **TASK-04**: Agent can abandon task and reset its status (abandon_task)
- [ ] **TASK-05**: Agent can run health check on beads state (health_check)
- [ ] **TASK-06**: Agent can load focused context bundle for a task (get_task_context)

### Worktree Tools

- [ ] **WKTREE-01**: Agent can start task in isolated git worktree with context bundle (start_task)
- [ ] **WKTREE-02**: Agent can rebase and merge task branch into main (merge_task)
- [ ] **WKTREE-03**: Agent can remove worktree and delete branch after merge (cleanup_task)
- [ ] **WKTREE-04**: Worktrees created at configurable path, not hardcoded ./worktrees/

### Quality Gate Tools

- [ ] **QUAL-01**: Agent can run tests with circuit breaker (run_tests)
- [ ] **QUAL-02**: Agent can run linter (run_lint)
- [ ] **QUAL-03**: Agent can run formatter (run_format)
- [ ] **QUAL-04**: Agent can request LLM-powered code review with staging (request_code_review)
- [ ] **QUAL-05**: Agent can commit only after approved review (attempt_commit)
- [ ] **QUAL-06**: Circuit breakers escalate after configurable max attempts

### Bridge Tools

- [ ] **BRDG-01**: Agent can import GSD plan as beads tasks with dependencies (import_gsd_plan)

### Session Tools

- [ ] **SESS-01**: Session recovery runs automatically on server startup when vibraphone.yaml detected
- [ ] **SESS-02**: Agent can explicitly call recover_session to check for stale sessions
- [ ] **SESS-03**: Session state persisted in .vibraphone/session.json

### Stack Tools

- [ ] **STACK-01**: Agent can reconfigure stack components and regenerate Justfile recipes (configure_stack)

### New Tools

- [ ] **NEW-01**: Agent can scaffold vibraphone into existing project via init_project
- [ ] **NEW-02**: init_project generates vibraphone.yaml from template with project-specific values
- [ ] **NEW-03**: init_project generates AGENTS.md and CLAUDE.md
- [ ] **NEW-04**: init_project generates .planning/vibraphone/ governance docs (CONSTITUTION.md, ARCHITECTURE.md, GLOSSARY.md, DECISIONS.md, prompts/reviewer.md, specs/_TEMPLATE.md)
- [ ] **NEW-05**: init_project appends Justfile recipes (creates Justfile if none exists)
- [ ] **NEW-06**: init_project appends .gitignore entries for .vibraphone/ and worktrees
- [ ] **NEW-07**: init_project does not overwrite existing files without explicit confirmation
- [ ] **NEW-08**: Agent can check for missing external dependencies via check_prerequisites
- [ ] **NEW-09**: check_prerequisites detects br, bv, git, just, node/npx and reports install commands

### Templates

- [ ] **TMPL-01**: Scaffolding template files bundled inside the Python package
- [ ] **TMPL-02**: Templates accessed via importlib.resources (not __file__-relative paths)
- [ ] **TMPL-03**: Templates match existing governance file formats from vibraphone-template

### Testing

- [ ] **TEST-01**: Unit tests with mocks for tool logic (subprocess calls mocked)
- [ ] **TEST-02**: Integration tests with real git/br for end-to-end tool flows
- [ ] **TEST-03**: Test that verifies installed wheel includes all template files

### Documentation

- [ ] **DOC-01**: README with project description, installation instructions, and quickstart
- [ ] **DOC-02**: Tool API reference documenting each MCP tool's parameters and return values
- [ ] **DOC-03**: Architecture documentation explaining how vibraphone works internally

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Distribution

- **DIST-01**: Package published to PyPI
- **DIST-02**: CI/CD pipeline for automated testing and publishing

### Multi-Agent

- **MULTI-01**: Full triage tool implementation (requires bv)
- **MULTI-02**: Full plan_parallel implementation (requires bv)

### Configuration

- **CFG-06**: User-level defaults at ~/.config/vibraphone/defaults.yaml
- **CFG-07**: Environment variable overrides for config values

### Reliability

- **REL-01**: Session recovery bug fixed (known issue from template)

### Task Management

- **TASK-07**: Agent can create task with dependencies (add_task) — deferred to prevent task sprawl; tasks should come from plan import or user manipulation

## Out of Scope

| Feature | Reason |
|---------|--------|
| PyPI publishing | v1 installs from git or local path; publishing adds CI/CD complexity |
| Standalone CLI commands | All interaction through MCP tools inside coding agents |
| .mcp.json registration | Users register via `claude mcp add vibraphone -- vibraphone` |
| Web UI / REST API | MCP-only interface; agents are the only consumers |
| Plugin system | Single package, no extension points needed for v1 |
| Cross-platform testing | Linux-first; macOS/Windows deferred |
