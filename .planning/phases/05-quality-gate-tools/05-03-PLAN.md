<task type="auto">
  <name>Task 2: Create request_code_review tool with staging and dangerous file blocking</name>
  <files>src/vibraphone/tools/quality_gate_tools.py</files>
  <action>
Create request_code_review tool with internal staging and LLM-powered review.

Per CONTEXT.md locked decisions:
- Review scope: Staged changes only - tool handles staging internally
- Dangerous files blocked: .env, .pem, .key, credentials.json, etc.
- Review outcomes: Any errors = REJECTED, warnings only = APPROVED, max exceeded = ESCALATED
- Previous issues passed to subsequent reviews

Tool signature:
```python
@mcp.tool
async def request_code_review(task_id: str, files: list[str] | None = None) -> dict:
    """Request LLM code review of staged changes.

    Args:
        task_id: Task ID for state tracking
        files: Optional list of files to stage (if None, stages all changes)
    """
```

Implementation steps:
1. Get unstaged changes via `git status --porcelain`
2. If files provided, filter to those files; otherwise use all unstaged
3. Filter out dangerous files using is_dangerous_file() helper:
   ```python
   DANGEROUS_PATTERNS = [r"\.env", r"\.pem$", r"\.key$", r"credentials", r"secrets?", r"private"]
   ```
4. Stage safe files via `git add`
5. Get diff via `git diff --staged`
6. Hash diff using hashlib.sha256().hexdigest()
7. Load quality state, get previous_issues
8. Call CodeReviewer.review(diff, previous_issues)
9. Determine status: any error severity = REJECTED, all warnings = APPROVED
10. Save state with last_review_status, last_review_diff_hash, last_review_issues, review_attempts
11. Check circuit breaker for review
12. Return structured output

Output format:
- status: "APPROVED" | "REJECTED" | "ESCALATED"
- issues: list of ReviewIssue dicts
- summary: str
- warnings: list of blocked dangerous files (if any)
- attempt: int
- next_steps: list[str]
</action>

<task type="auto">
  <name>Task 3: Create attempt_commit tool with review enforcement</name>
  <files>src/vibraphone/tools/quality_gate_tools.py</files>
  <action>
Create attempt_commit tool that enforces review-before-commit workflow.

Per CONTEXT.md locked decisions:
- Precondition 1: Review must be APPROVED
- Precondition 2: Staged diff hash must match reviewed diff (no sneaking in changes)
- Precondition 3: `just check` (or configured command) must pass
- All pass: Execute `git commit -m "{message}"`

Tool signature:
```python
@mcp.tool
async def attempt_commit(task_id: str, message: str) -> dict:
    """Attempt to commit changes. Requires approved code review.

    Args:
        task_id: Task ID for state verification
        message: Commit message
    """
```

Implementation steps:
1. Load quality state for task_id
2. If state is None or last_review_status != "APPROVED":
   - Return error: "No approved review found. Run request_code_review first."
   - Include next_steps: ["Run request_code_review(task_id) to get approval"]
3. Get current staged diff via `git diff --staged`
4. Hash current diff
5. If hash != last_review_diff_hash:
   - Return error: "Staged changes differ from reviewed changes. Re-review required."
   - Include next_steps: ["Run request_code_review(task_id) again"]
6. Run quality gate check via run_command(get_command("check", config))
7. If check fails:
   - Return error with check output
8. Execute `git commit -m "{message}"`
9. Return success with status: "committed"

Output format:
- status: "committed" | "error"
- message: str (commit hash on success, error message on failure)
- next_steps: list[str]

This tool is the gatekeeper that enforces all quality gates before allowing commits.
</action>

  <done>attempt_commit tool exists with @mcp.tool decorator. Enforces APPROVED review status, matching diff hash, and passing quality check before executing git commit. Returns "committed" or "error" status.</done>
